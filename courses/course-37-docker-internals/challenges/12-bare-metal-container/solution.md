# Solution: Bare Metal Container

## Method 1: chroot (simple, educational)

`chroot` changes the root directory for the current process and all child processes. It's the original Unix isolation primitive — `chroot` jails existed decades before Docker.

```bash
sudo chroot /tmp/dojo-rootfs /bin/sh

# You are now inside the rootfs
cat /secret/flag.txt
# KUBE{unshare_pivot_root_no_docker}
```

**What chroot does:** it calls the `chroot(2)` syscall to change what the kernel reports as `/` for this process tree. The old root is still accessible to the host — this is not a true container (a process with enough privileges can break out).

## Method 2: unshare + pivot_root (the real container way)

This is what runc does, stripped to its essence.

```bash
ROOTFS="/tmp/dojo-rootfs"

# Step 1: Bind-mount the rootfs onto itself
# pivot_root requires the new root to be a mount point
sudo mount --bind "$ROOTFS" "$ROOTFS"

# Step 2: Create the old-root mount point inside the rootfs
mkdir -p "$ROOTFS/old-root"

# Step 3: Enter new namespaces
sudo unshare --fork --pid --mount --uts --ipc /bin/bash <<'CONTAINER'
  cd /tmp/dojo-rootfs

  # Step 4: Mount /proc for the new PID namespace
  mount -t proc proc /tmp/dojo-rootfs/proc

  # Step 5: pivot_root — make the rootfs the new /
  # The first arg is the new root; the second is where to put the old root
  pivot_root . old-root

  # Step 6: Unmount old root (lazy — won't block on busy mounts)
  umount -l /old-root

  # We are now inside the container
  echo "Hostname: $(hostname)"
  echo "PID 1 is: $$"
  cat /secret/flag.txt
CONTAINER
```

## What each piece does

| Command | Kernel feature | What it isolates |
|---|---|---|
| `unshare --pid` | `clone(CLONE_NEWPID)` | The process gets its own PID space; it sees itself as PID 1 |
| `unshare --mount` | `clone(CLONE_NEWNS)` | Mount operations don't propagate to the host |
| `unshare --uts` | `clone(CLONE_NEWUTS)` | Hostname/domainname are independent |
| `unshare --ipc` | `clone(CLONE_NEWIPC)` | Shared memory, semaphores are isolated |
| `pivot_root . old-root` | `pivot_root(2)` syscall | Changes the root mount for this mount namespace |
| `umount -l /old-root` | Lazy unmount | Detaches the host filesystem from visibility inside |

## chroot vs pivot_root

| | `chroot` | `pivot_root` |
|---|---|---|
| Breaks out with `chroot(".")` | Yes (if root) | No — pivot_root requires a full namespace change first |
| Changes `/` for the filesystem | No — the original root is still reachable | Yes — the old root is fully unmounted |
| Used by Docker/runc | No | Yes |
| Requires mount namespace | No | Yes |

`chroot` is a convenience hack. `pivot_root` inside a mount namespace is the real deal.

## Adding cgroups manually

For a full container you'd also limit resources:

```bash
# Create a cgroup for our container
mkdir -p /sys/fs/cgroup/my-container
echo "50000 100000" > /sys/fs/cgroup/my-container/cpu.max    # 50% CPU
echo "67108864" > /sys/fs/cgroup/my-container/memory.max     # 64 MiB

# Add our shell PID to the cgroup
echo $$ > /sys/fs/cgroup/my-container/cgroup.procs
```

runc does exactly this, reading the values from the OCI runtime spec JSON that `docker run` generates before calling runc.

## What runc adds on top

- Parses the OCI runtime spec (`config.json`) generated by containerd
- Sets up `/dev/null`, `/dev/zero`, `/dev/random`, `/dev/tty` device nodes
- Applies seccomp profiles (blocks dangerous syscalls)
- Applies AppArmor or SELinux labels
- Runs OCI lifecycle hooks (`prestart`, `createRuntime`, `poststart`, `poststop`)
- Handles signals and passes them to PID 1

The core loop — namespaces + rootfs + cgroups + exec — is exactly what you just did.
